Security

  • One public entry. The ALB is internal; only CloudFront's managed security group may reach it.
  • Inbound paths: ALB → tasks :3000, API → DB :5432. Nothing else.
  • Database: TLS required by the server; the API verifies the RDS CA and hostname; read-only app login.
  • Secrets: Secrets Manager, injected by ECS; master password managed by RDS. None in Git, images or Terraform.
  • IAM: one execution role per service; task roles with no permissions; web cannot read the DB secret.
  • CI: plan (read-only), release and infra roles. Deploy credentials only on protected main.
  • Containers: Alpine, non-root, read-only filesystem, pinned by digest, scanned on push (0 findings).
  • Encryption at rest: RDS, S3, ECR.

Continuous delivery

  • Every branch: tests, a check that CI is read-only, Terraform plan. Main: build and one serialized release job.
  • The release waits for all checks; only one release runs at a time; image digests come from ECR by the commit tag.
  • CI runs in a separate GitLab project on an owned runner; the code repository itself needs no runners.
  • AWS access through scoped roles. OIDC is configured, but this GitLab issues no ID tokens, so CI users can only assume those roles.
